ARC Tower Architecture

Data plane + control plane. Client agents push OpenTelemetry using env variables, platforms are pulled by connectors, and everything passes one Collector gateway before it reaches Loki, Prometheus and Langfuse. The ARC Tower app provisions every piece per client product from its registry. Mapped to the deck's five layers.

How the push path works: agents send OpenTelemetry using env variables

The env variables don't create telemetry. They configure the OpenTelemetry SDK that is already running inside the agent's process. At startup the SDK reads the standard OTEL_* variables, which tell it where to send spans, how to authenticate, and how to label them. It then batches the spans and sends them as HTTP POST requests. No SDK in the process means nothing is sent.

The variables (OpenTelemetry standard, read by every OTel SDK)

VariableExample / purpose
OTEL_EXPORTER_OTLP_ENDPOINThttps://ingest.arctower.<org>/otlp
Base URL. The SDK adds /v1/traces, /v1/metrics, /v1/logs itself.
OTEL_EXPORTER_OTLP_PROTOCOLhttp/protobuf
Set it explicitly: some Python setups default to gRPC, and Langfuse accepts HTTP only.
OTEL_EXPORTER_OTLP_HEADERSx-arc-key=arc_live_abc123
Auth header issued by ARC Tower at onboarding. Comma-separated key=value, values URL-encoded.
OTEL_SERVICE_NAMEclaims-assistant
App name; becomes the service/agent name in dashboards.
OTEL_RESOURCE_ATTRIBUTESarc.agent.id=claims-bot,deployment.environment=prod
Extra labels added to every span.
OTEL_TRACES_EXPORTERotlp (default for auto-instrumentation)
OTEL_METRICS_EXPORTER
OTEL_LOGS_EXPORTER		none or otlp: turn metrics and logs on or off.

Some instrumentation libraries have their own switch for prompt/response text, e.g. OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT=true for the official OpenAI instrumentation. Whether it's on follows the content-capture policy agreed with each client.

Standard client env block (through the ARC gateway)

OTEL_EXPORTER_OTLP_ENDPOINT=https://ingest.arctower.<org>/otlp
OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
OTEL_EXPORTER_OTLP_HEADERS=x-arc-key=<ingest key>
OTEL_SERVICE_NAME=claims-assistant
OTEL_RESOURCE_ATTRIBUTES=arc.agent.id=claims-bot,deployment.environment=prod

PoC shortcut (straight to Langfuse, skips the gateway)

OTEL_EXPORTER_OTLP_ENDPOINT=https://<langfuse-host>/api/public/otel
OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
OTEL_EXPORTER_OTLP_HEADERS=Authorization=Basic%20<base64(public_key:secret_key)>

No tenant tagging, PII masking or Prometheus metrics until the gateway is in place.

Where the client sets them

Wherever the app's environment is configured: a .env file, the Kubernetes Deployment env: section, Docker Compose, Azure App Service settings, or a CI/CD variable group. It's a configuration change, not a code change.

Where the spans come from (this decides whether "env only" works)

ENV VARS ONLY

1 · Framework already emits OTel

Native OTel frameworks such as Strands Agents, Semantic Kernel and Pydantic AI. LangChain/LangGraph through LangSmith's OTel mode (LANGSMITH_TRACING=true, LANGSMITH_OTEL_ENABLED=true, plus a flag to stop sending to LangSmith itself; confirm names in current LangSmith docs).

NO CODE EDITS · PACKAGES + START COMMAND

2 · Zero-code auto-instrumentation

pip install opentelemetry-distro opentelemetry-exporter-otlp \
  openinference-instrumentation-langchain
opentelemetry-instrument python app.py

Patches the libraries at startup and reads the same OTEL_* variables.

ENV VARS ONLY

3 · Client already instrumented with OTel

Their code already sets up an OTel tracer and exporter. The env variables just point it at ARC Tower.

ENV VARS DO NOTHING

None of the above

No SDK is running to read the variables. Use option 2, or onboard through a pull connector if the agent runs on a platform (Azure Foundry, Bedrock, ServiceNow, Salesforce).

Push path: the only client change

  • The client adds the standard OTEL_* env block. The ingest key comes from ARC Tower onboarding.
  • Works as env-only when the app already emits OTel. Otherwise, auto-instrumentation needs packages + a start command, but no code edits.
  • PoC shortcut: point the same variables straight at Langfuse.
  • Full details are in "How the push path works" above.

Control plane: what onboarding provisions

  • Registry: tenant, product and a hashed ingest key. The proxy reads it to map key → tenant.
  • Langfuse: a project and key pair per product, created through its API. Keys are kept in Vault.
  • Grafana: a folder or org with template dashboards and alert rules from the KPI targets.
  • Connectors: config in the registry and secrets in Vault, picked up by the workers.
  • SSO: Entra ID for both the ARC app and embedded Grafana.

Onboarding flow (deck slide 4)

  1. Identify & connect. Create a product and pick a connector card.
  2. Ingest. Copy the env block or fill in credentials. Test connection waits for the first span.
  3. Map & standardise. A coverage score shows which gen_ai.* fields are arriving.
  4. KPIs & targets. Templates are applied; the client sets budgets and SLOs.
  5. Alerts. Grafana rules are generated from the targets.
  6. Dashboard. Templates go live, with trace drill-down in Langfuse.

Design rules

  • The tenant comes from the ingest key at the gateway, never from the client's payload.
  • PII is masked in the Collector before anything is stored.
  • Dashboards read Prometheus and Loki, not Langfuse's internal ClickHouse tables. Cost enters Prometheus through the FinOps job using Langfuse's public API.
  • Grafana queries the stores directly, isolated by org/folder per tenant. The ARC app enforces the tenant on its own queries.
  • Skip MLflow and Tempo at first because Langfuse already covers traces and evals.

Delivery phases

  • 0 · PoC (built): all layers running natively on one machine via start.py - no Docker - with a sample agent onboarded through env vars only, a demo pull connector, and Langfuse Cloud as the trace store.
  • 1 · MVP: registry, push-only onboarding, auto-provisioning, agent registry and standard dashboards.
  • 2 · Platforms: Azure Foundry and Bedrock connectors, Vault, FinOps, Loki events and Mimir.
  • 3 · Full tower: ServiceNow and Salesforce connectors, intelligence jobs, executive views and APIs.
